# v2.1.2-beta.1 — Home Assistant 2026.11 compatibility

This is an opt-in beta prerelease from `senyo888-patch-1`. Current Stable remains
v2.1.1, and `main` is unchanged.
[Release and install asset](https://github.com/senyo888/humidity-intelligence/releases/tag/v2.1.2-beta.1).

## Changes

- Package only the integration in `humidity_intelligence.zip`, with its manifest
  at the ZIP root. This avoids the oversized repository archive reported in
  [#145](https://github.com/senyo888/humidity-intelligence/issues/145).
- Recognize Marketplace and legacy HACS update entities by repository identity.
  Missing or ambiguous provider evidence remains unverified. Optional dashboard
  cards remain independent of the backend.
- Normalize VOC to ppb, CO/CO₂ to ppm and PM2.5 to µg/m³ before control, aggregation
  and Stability evaluation. Unsupported units and invalid values remain excluded.
- Preserve the CO emergency latch until every configured source provides valid
  readings below the clear threshold for a fresh, continuous two-minute hold.
  Missing or invalid readings reset the hold; valid high readings still activate
  the highest-priority emergency. Existing thresholds and lane priority remain.
- Preserve hidden settings in conditional gate forms, retain explicitly saved
  slope source identities, and retain runtime custody when platform unloading fails.
- Advance both V2 layouts to UI revision 14, with stamp schema and generator 1.

## Installation and migration

Enable beta versions for HI in Marketplace and select `v2.1.2-beta.1` explicitly.
The GitHub **Source code** archives are not the install asset; use the named
`humidity_intelligence.zip` asset when handling the package manually.

After an upgrade, fully restart Home Assistant, verify the loaded version, then
export and replace the complete saved V2 Manual-card YAML. Restart clears
in-memory Stability sampling history. Existing saved cards are not updated
automatically.

Review sensor units and retain thresholds in HI's canonical units. Sources,
thresholds and historical records are not automatically migrated. Ambiguous legacy
supplied-slope mappings require explicit correction in Options. See
[compatibility and migration](../home-assistant-2026.11.md).

Keep a complete previous package and compatible saved cards for rollback, with
backup directories outside `custom_components`. Do not delete configured entities
to recover from a download failure. Stable v2.1.1 retains its oversized archive;
[exact-tag manual recovery](../release-packaging.md#earlier-versions-and-current-evidence-limits)
remains available. This release does not change earlier tags or assets.

## Validation and limits

The runtime and generated-card changes passed 991 Python tests plus 314 subtests,
256 JavaScript tests, and native checks on Home Assistant 2026.5.1, 2026.10.1 and
2026.11.0. The subsequent release-preparation delta changes documentation only;
the exact final ZIP is rebuilt and verified separately.

Post-publication Marketplace tests passed on Home Assistant 2026.11.0 on
7 November 2026:

- Upgrade: Marketplace installed the beta over a manually installed and loaded
  v2.1.1 baseline. After a full restart, the beta loaded with the original
  configuration intact. This does not prove automatic update notifications from
  a Marketplace-managed v2.1.1 installation.
- Fresh install: after uninstalling HI and restarting with its package and config
  entry absent, Marketplace downloaded the beta and the native setup flow created
  a new, loaded entry. The test used alert-only mode with no mapped outputs.
- Both installations matched all 78 files in the published ZIP. The original HI
  configuration was restored and verified after the test, with no HI errors or
  outstanding Repairs.

These tests used Home Assistant's native Marketplace and config-flow APIs. They
do not claim browser rendering, a legacy HACS installation, sustained soak or
physical-device response. Earlier direct Lab validation separately covered
diagnostics, conditional forms and generated revision-14 exports; live rendering
of replaced revision-14 cards remains untested.
